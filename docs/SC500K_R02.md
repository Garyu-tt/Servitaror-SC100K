# SC500K R02: dense synaptic crossbar memory

Replaces per-word recurrent storage with packed Q4 coefficient pairs (1/7) in a two-dimensional synaptic matrix. Row and column selectors evaluate weighted threshold circuits. A sparse scheduler selects the sole firing row from emitted spikes, not directly from the guest address; column read and hold/write gates evaluate all 64 words in that row. The host still implements routing, tensor storage, programming rules and checkpointing. Volatile RAM is now resettable synaptic working memory, not persistent recurrent spike-state RAM. Disk uses the same substrate with persistent checkpointing. No guest-byte shadow. This is a specialized crossbar model, not an integrated or biologically trained GENESIS graph.

RAM 2 MiB (8192 x 64 x 32 bits); disk 1 MiB (4096 x 64 x 32 bits); packed coefficient arrays total 24 MiB, 50331648 independent Q4 coefficient entries. An explicit five-by-five replica expansion would require 1258291200 memory synapses before other wiring. Estimated logical cell allocation 460610 (123110 prior core, 187870 RAM, 146260 disk, 3370 graphics); not a measured unified graph count. Capacity increases do not imply free physical memory or compute. 2 MiB RAM and 1 MiB disk remain insufficient for the current 6 MB Linux image.

Local PASS: exhaustive 12416 row/column selector cases, 654 RAM read checks, three ablations, malformed coefficient pair rejected without changing state, 21 real RV32I guest instructions fetched from neural storage, high RAM and end-of-disk MMIO read/write, restored disk and 8x8 graphics. No claim of full ISA conformance or Linux boot on SC500K. Reproduce with `python neural_crossbar_r28.py --build-dir /tmp/sc500k-crossbar`. SC100K Linux checkpoint retained separately.
